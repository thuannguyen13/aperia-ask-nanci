Ask Nanci · Interaction Model · Internal Briefing

One Interaction Model.
Two Panels, Two Contexts.

Ask Nanci works from the same two-panel model everywhere: a main panel that's always present, and one second panel that opens and closes around it. What changes is what the second panel is — a Nanci-built artifact in the standalone app, or a running chat conversation in an integrated product, where generated content renders as generative UI inline in that same chat.

01 · Summary

The Same Two Panels, Applied To Two Different Home Screens

One main panel, one second panel, three gates that decide what happens in the second panel. What changes between contexts is what that second panel actually is.

Direction

Main Panel Never Closes

Standalone: the main panel is the chat thread. Integrated: the main panel is whatever product screen is open. Either way, only the second panel can be opened or closed.

Theme

Three Gates, Both Contexts

G1 (action needed), G2 (stays in view), G3 (too dense for chat) apply unchanged in both contexts. If none of the three fire, the response stays inline — no panel opens.

Positive

Integrated Apps Reuse Real Screens

Where a native screen already exists — a case, a queue, a form — Nanci navigates the main panel to it and pre-fills it. Anything without a native screen renders as generative UI inline in the chat instead.

Decided

The Second Panel Is Always Chat, Integrated

In the integrated app, the second panel never switches away from the conversation. A table, a chart, a form — anything Nanci generates beyond the main page — renders as a generative UI card inline inside the chat itself.

03 · The Gate Test

Three Gates Decide What Happens In The Second Panel

Evaluate top to bottom — first match wins, and a later gate is never checked once an earlier one fires. If none of the three fire, nothing opens or generates; the response stays inline.

G1
Action needed auto-open
Edit, approve, submit, sign, dispute, upload — something the user needs to do. Standalone: the second panel opens with the form or confirmation. Integrated: the main panel navigates to the real screen and pre-fills it when one exists; when it doesn't, Nanci renders a generative UI form inline in the chat instead.
G2
Stays in view across turns auto-open
Content the user will keep referencing this turn and the next — a case, a merchant profile, a report they're asking follow-ups about. Standalone: the second panel opens and holds it as the one artifact view. Integrated: it renders as a generative UI card inline in the ongoing chat, staying in the scrollback to reference. A comparison is a single view — for example a two-column table — never two panels side by side; there's no multi-panel support.
G3
Too dense for chat offer
More than a few items, a chart, more than about 80 words. Auto-opens only when the user used a display verb (show, open, pull up, list, compare); otherwise Nanci summarizes inline and offers it. Integrated: this means a generative UI table or chart card appended inline in the chat, unless a native report screen already exists, in which case the main panel navigates there instead.
—
No gate fires stays inline
Facts, statuses, confirmations, clarifying questions, short explanations, errors. Answered inline as plain chat text, wherever the user is already typing — the main chat panel in the standalone app, or the chat dock in the integrated one. No generative UI, nothing opens or closes.

06 · Lifecycle

How The Second Panel Behaves Once It's Open

Opening is one decision. Replacing, keeping, and closing are the ones users actually notice — and the main panel is never part of this lifecycle, since it never closes.

01
Every generated card is announced inline
The chat always carries a one-line lead-in for what a generative UI card is and why it appeared — it's never dropped in silently.
02
Only the second panel opens or closes
The main panel is permanent. Standalone replaces the one open artifact with a new result. Integrated appends generated content as a card inside the ongoing chat instead of replacing anything.
03
Unsaved input blocks replacement
If an open artifact or card holds user-entered data, confirm before replacing or navigating away from it. Never discard silently.
04
Dismiss preserves state
Closing the second panel is a view change, not a reset. Reopening within the session restores scroll, filter, and form state.
05
Nanci doesn't close the second panel
The only exception is a completed task, confirmed inline in the same turn.
06
Follow-ups update in place
"Filter that to last 30 days" refreshes the current artifact (standalone) or the specific generative UI card (integrated) — it never opens a new panel or appends a duplicate.
07
Mobile raises the bar
Only G1 and explicit display verbs auto-open the second panel on mobile. G3 always offers.
08
The second panel never covers the answer
If layout forces overlap, the inline summary in the main panel has to stand alone without it.

07 · Open Decisions

What Still Needs A Team Decision

The shared rules resolve most cases. These two don't have a documented answer yet and should be settled before scenarios are finalized.

Resolved: no multi-panel, for now. The model is a main panel plus a single second panel — G2 content and comparisons render as one view, never as parallel or tabbed panels.
Resolved: in the integrated app, the second panel is always the chat conversation. Anything Nanci generates that isn't part of the main page — a table, a chart, a form — renders as generative UI inline inside that chat, never as a separate panel replacing it.
Chat persistence across pages, integrated: if chat is scoped per page, does leaving a page discard that page's Nanci thread, or does it stay retrievable later — a per-page chat history, similar to the standalone app's sidebar?
Connected-account placement, integrated: Business Owner surfaces (VisionWeb, AccessOne) already show bank-linking even though the product owns the core data — should account linking live in Nanci's own settings, or the product's existing settings module?

08 · Recommendation

Document Once, Apply Twice

The two-panel model, the three gates, and the lifecycle rules are a single spec. Context only changes what the second panel is and how generated content shows up inside it.

The Recommendation

Write the two-panel model, the three gates, and the lifecycle rules as one shared spec. Layer a short "second panel resolution" appendix on top for each context — standalone resolves the second panel to a built artifact; integrated resolves G1 to the main panel's real screen first, and generative UI inline in the chat as the fallback everywhere else. That keeps the behavioral model single-sourced while letting each product read correctly.

Standalone default

Main panel is chat. Second panel is always a Nanci-built artifact.

Integrated default

Main panel is the product screen. Second panel is always the chat conversation; anything generated beyond the page renders inline as generative UI within it.

The Ask

Resolve the two open decisions in section 07 in a working session with Design and Engineering, then lock the second-panel-resolution appendix so scenario writing can proceed against a settled model rather than case-by-case judgment calls.
