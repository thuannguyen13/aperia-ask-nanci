What adapts, what does notEight aspects, and the gap in each

Where the app already handles a phone, where it does not, and which of the gaps the design system could close for us.

Typography

Type needs the least work of anything here. It never changes size between a computer and a phone, and mostly it does not need to.

What we have
Panel type is already dense: a 9px label over a 12px value, built for a narrow column
It holds at 390px, and there is no smaller scale beneath it to reach for
Body copy wraps rather than shrinking
What is missing
Nine of the eleven files containing inputs miss the 16px minimum, so iOS zooms the page when the field is focused
No line-length cap, so a paragraph runs the full width of a wide panel
The design system offers no type-scale guidance, so every decision here is ours

Sizing

Controls are sized for a pointer on every screen. Nothing grows for touch, and the design system has no opinion about it either.

What we have
Four consistent sizes: 24, 28, 32 and 36px
The send button was raised to 32px to match the design
What is missing
No size reaches 44px, the minimum Apple and Material both give for touch
Zero responsive size variants exist, so a phone gets exactly what a 1440px screen gets
At phone density 28px is roughly 4.7mm of glass against the 9mm a fingertip needs
Shadcn ships no touch-target guidance, and its own default button is 36px

Mobile-Specific Behaviors

The one area with real mobile work. Two surfaces change shape below the breakpoint, and several hooks exist only for phones.

What we have
The Sidebar becomes a drawer over the conversation, 288px, from one button
The panel becomes a sheet that rests as a handle above the message box
A drag gesture with velocity, a scroll handoff, and a scrub that recedes the conversation
Keyboard inset and composer inset published and tracked live
The conversation is hidden from screen readers while a sheet is open
What is missing
No safe-area insets anywhere. Zero uses of env(safe-area-inset), so the composer sits in the home indicator on newer iPhones
Panel swap and close do not animate
One panel is reachable at a time, and the resting handle does not say which

Charts

Recharts sizes a chart to any box and thins its own axis ticks. We have switched that thinning off, and we are one version behind a fix for the legend.

What we have
ResponsiveContainer in five places, so a chart fills whatever box it is given
Recharts thins colliding tick labels by default (interval="preserveEnd")
The legend was rebuilt as a normal element beneath the chart, so it wraps and takes its real height
Tooltips already respond to a tap
What is missing
We set interval={0} in three charts, which forces every tick and disables the one adaptation Recharts gives us
We are on recharts 3.8.1, which has a legend-overlap regression fixed in 3.9.0. Bumping is a free win
The responsive prop (3.3+) supersedes ResponsiveContainer and drops its sized-parent requirement, which is what bites in flex layouts
Default chart margin is 5px on every side, so long or rotated labels clip
Tooltips still trigger on hover, where trigger="click" suits a phone

Table

Handled, but not by us. The design system already shipped the fix, and we added a second one on top that does nothing.

What we have
Shadcn's Table ships its own scroll container, and that is the element that actually scrolls
Nothing is hidden and nothing restacks into cards, so the figures keep one order
No panel hand-rolls a table, so the treatment is universal
What is missing
Our extra wrapper is inert. We added a second overflow-x-auto around a table that was already wrapped; measured on a phone, it never scrolls
No cue that columns continue past the right edge
No sticky first column, and shadcn ships neither that nor column priority

Tab And Segmented Controls

A tab strip wider than the screen loses its tabs. Shadcn has never fixed this, so the fix is ours and it is opt-in.

What we have
SegmentedGroup takes a scrollable prop that wraps it in a scroll area
Labels never shrink, so nothing becomes unreadable
What is missing
Opt-in, not default. A plain TabsList still clips
Shadcn ships nothing for tab overflow and no official scrollable example. The community issue was closed stale
No edge fade or arrow to say more tabs exist, and the selected tab is not scrolled into view

What Shadcn Gives Us

More than we use. One thing we hand-built already existed in the system, and we arrived at the same number it did.

What we have
Sidebar swaps to a Sheet below 768px at a built-in SIDEBAR_WIDTH_MOBILE of 18rem
Table ships a horizontal scroll container
Sheet, Drawer and ScrollArea are all available
The responsive-dialog pattern is official: Dialog on a computer, Drawer on a phone
What is missing
We do not use the Sidebar primitive. Ours reimplements the swap and independently landed on 288px, which is that same 18rem
No breakpoint hook is exported. It exists inside the bundle but is reachable only through useSidebar(), so ours is hand-built
The official responsive-dialog example depends on a media-query hook that is not shipped
The Drawer could not carry the panel sheet: it renders in its own portal, over the composer, and keeping the composer usable is the point
Nothing on touch targets or type scale

What Recharts Gives Us

It makes a chart fit any width and thins its own ticks. Everything about the width being small is left to us.

What we have
ResponsiveContainer measures the parent and redraws at its size
Tick thinning is on by default, and it measures the label text to decide
Touch is wired through: tooltips answer a tap, and Brush drags
A newer responsive prop removes the sized-parent requirement
What is missing
The built-in Legend is absolutely positioned and never reports its height, so the space for it is a fixed guess: too small and it clips, too big and it leaves a gap. We replaced it
Neither ResponsiveContainer nor ChartContainer is legend-aware, so that guess sits on top of both
No mobile mode of any kind. Label formatting, tick density, margins and legend placement are all ours
Nothing widens the 5px default margin as labels grow
