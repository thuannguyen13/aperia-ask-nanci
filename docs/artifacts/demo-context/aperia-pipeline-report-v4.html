Why This Matters

Today, turning a Figma design into shipped code is a manual translation step: a developer reads the frame, guesses spacing and color values, hand-writes markup, and hopes the imports and prop names match what the design system actually ships. Mismatches surface in review, or later in production.

Where this sits: This pipeline is agentic engineering, not vibe coding — Code Connect gives the AI a formal spec (which Figma component maps to which aperia-ds5 import), Storybook is a living reference for correctness, and every release is versioned rather than copy-pasted. The AI generates within guardrails the team controls, instead of generating freely and fixing mistakes after the fact.

The trade

The cost is upfront: building and maintaining aperia-ds5, the Code Connect mappings, and the Figma kit setup. The payoff is ongoing — every future screen and every future project draws from the same verified source instead of re-deriving it by hand, and design drift stops compounding project to project.

02

Implementation at a Glance

The library (aperia-ds5) wraps shadcn/ui + Radix, is bundled with tsup, and ships a single base.css theme file. Projects install it via npm or a monorepo workspace, override a handful of brand tokens by hand, and import components directly.

Full stack, token architecture, directory layout, dependency rules, and step-by-step workflows are documented in the companion Implementation Reference — this overview stays at the decision level.

✓
ShadcnDesign
shadcn-endorsed kit with 2,000+ components, component-level Figma Variable linkage, and a Figma plugin that generates shadcn/ui component code from frame selections. Includes Agent Skills for Claude, Cursor, and Codex. Actively maintained.
Agent Skills vs Code Connect: ShadcnDesign's Agent Skills output code against stock shadcn/ui imports. Code Connect (.figma.ts files) additionally maps those components to aperia-ds5 specifically. Both are needed — Agent Skills for broad context, Code Connect for the correct package.
05

Design Decisions

Key choices made in this pipeline and the reasoning behind them.

Figma kit — ShadcnDesign

The shadcn-endorsed Figma kit. Chosen because it mirrors the shadcn/ui component model 1:1, ships with Agent Skills for Claude and Cursor, and has component-level Figma Variable linkage. This means Code Connect mappings stay accurate without custom maintenance.

Token approach — designer hands off, developer writes

No automated token export pipeline. The designer provides the values directly (brand color, radius, etc.) and the developer writes them as CSS custom property overrides in the project's theme file. Brand tokens change infrequently — typically once at project setup — so a 5-line :root block is faster and simpler to maintain than a sync pipeline.

Token ownership — library ships defaults, project overrides

The library (aperia-ds5) ships a complete default theme in base.css. Each consuming project imports it and only overrides what differs. This keeps project setup minimal while giving full control over brand identity.

Distribution — monorepo or published npm

Both models are supported. Use workspace:* when all consuming projects live in the same repo. Publish to npm (or GitHub Packages) when projects are in separate repos or maintained by different teams. The library's public API is identical in both cases.

Framework agnosticism

The library has no framework dependency — React is declared as a peer dependency only. Consuming projects bring their own React and framework (Next.js, Vite, Remix, etc.) without version conflicts.

What's already governed

Guardrails in place today: Code Connect prevents the AI from guessing wrong imports or prop names. Versioned npm releases mean a library change never silently changes a shipped project. Storybook documents every component and variant as the source of truth reviewers can check against.

Open questions

Not yet solved: Version sync strategy between the Figma kit and the npm package is not yet defined. Workflow for net-new components beyond shadcn (custom Aperia-specific components) is also not yet established.
