04

AI Prompting Best Practices

These were derived directly from the Mail showcase build. The correction pass that was needed revealed where the process broke down, and each practice below addresses a specific failure mode.

Practice 01

Fetch the design before writing any code

Always call get_design_context first and read the screenshot. Never infer layout from a text description — the screenshot reveals structural decisions (inline vs. stacked, card vs. row) that words don't convey.

Practice 02

Read section by section, not all at once

Go through each panel in order — toolbar → header → list item → detail. For each section, note every icon name, prop value, and layout decision explicitly before moving to the next.

Practice 03

Extract all static content from Figma

Never invent counts, labels, or nav items. Pull exact values from the design output (e.g. nav group count, badge numbers, exact copy). Invented values look plausible but create drift from the design spec.

Practice 04

Split fetch + implement into two messages

First message: fetch the design, describe the spec back. Confirm with the developer. Second message: implement. The extra round-trip costs less than a full rewrite pass.

Practice 05

Give AI precise coordinates, not vague requests

Include file path + line + what's wrong + what you want. "In mail-list.tsx:28, the filter runs on every render — memoize it" costs a fraction of "fix the mail component."

Practice 06

Use /compact proactively

Once a major task is complete, run /compact before starting the next one. This clears accumulated tool output from context, keeping subsequent generations faster and more accurate.

Practice 07

Prefer targeted edits over file rewrites

Describe what specifically to change rather than asking to rewrite the file. A precise Edit call is faster and less likely to introduce unintended side-effects than a full Write.

Practice 08

Batch related questions into one message

Instead of asking about component availability one at a time, list all of them in a single message. Each round-trip has overhead — batch independent questions to minimize it.

Key insight: The most expensive AI mistake is starting to code before fully reading the design. Two extra minutes extracting a layout spec from the Figma output prevents a full rewrite round, which costs far more in both time and tokens.

The prompt template that works

# Step 1 — fetch and spec (first message)
"Fetch this Figma frame and give me the implementation spec for approval:
[figma URL]
Do not write any code yet."

# Step 2 — implement (after approval)
"Implement the spec as approved. Use aperia-ds5 components.
Target file: app/[page]/page.tsx"

# For targeted fixes
"In components/mail/mail-list.tsx line 28,
the tabs position should be inline with the Inbox heading — move it."
