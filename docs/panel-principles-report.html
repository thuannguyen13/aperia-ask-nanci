The Panel Model
Four Parts, Three Triggers, One Cascade

No panel appears that the user did not ask for, and how they asked never matters: typing and clicking express the same intent, and the same intent always does the same thing. Click along with the demos below.

01 · Summary

Two Pillars Carry The Whole Model

One says what a panel is, the other says why anything on screen ever changes. Everything else in this report follows from them.

Definition

A Panel Is A Surface The User Works On

It opens beside what they are doing, never over it, so they can use both surfaces at once without leaving either.

Intention

Intent Decides What Happens Next

Every change on screen is a user intent, and each intent has exactly one outcome, so nothing moves unless the user meant it to.

First Question: Page, Modal, or Panel?

Do you still need what is on screen? Use
No A new page
Yes, but this must be handled first A modal
Yes, and the user works between the two A panel

A panel opens beside its origin, never over it. The origin stays usable.

03 · Interactions

Play The Model, Then Read The Rules

Every way of opening something is one of three triggers: navigate, summon, or drill. The behavior binds to the trigger, never to who fired it, so Ask Nanci and any product feature emitting the same trigger behave identically, with no coordination between teams. Play first; the triggers and rules below cover every case.

How This Mode Works

Three moves. Opening puts things in the next panel over, ✕ closes a panel and everything after it, and the rest just updates in place. The breadcrumb shows the path that no longer fits; click a step to go back.

Trigger Means What happens The way back
Navigate Take me somewhere Replaces Primary and clears everything beside it. The only trigger that may touch Primary, which is what protects the conversation while you work from it. High bar: it changes what the user is looking at The menu's own selected state
Summon Give me this alongside what I am doing Opens a panel beside, additive. Never touches Primary Triggered conversationally, it leaves a card in the thread; the thread is the trail back
Drill Go deeper on this thing in front of me Stacks a child below its parent, anchored to it, and closes with it. It stacks while there is room; when full, the deepest panel refreshes in place and the breadcrumb extends The parent it came from, or a breadcrumb step

The Four Rules Of Getting Around

01
Forward Only
A panel can change itself and the panels after it, never the panels before it. So inside a panel you can only go deeper; new things open from the conversation or the menu. Navigate is the only exception, because you asked to go somewhere else.
02
Room Is Limited
Only a few panels fit on screen. When there is no room left, going deeper uses the last panel again, and the breadcrumb remembers your path.
03
Always A Way Back
You can always bring a view back: click your old message, or use the breadcrumb. It comes back with live data, not an old copy.
04
Never Opens By Itself
A panel never opens or closes by itself. Nanci can send a message with a button, but only your click opens the panel.
You do What happens
Plain click Loads in the panel you clicked, like a web page. The breadcrumb is that panel's history
Hold Shift and click, or the ⇧ toggle Opens it as a panel beside or below instead. You decide the placement, never the system
An experiment in user-controlled placement, not the model. The system never guesses where things should open; the modifier decides. The open question is discoverability: side-by-side work only happens when the user knows the key, which is why the tooltip, the ⇧ chip, and the held-Shift highlight exist.

04 · Ship Tests

Check Every Panel Before It Ships

A panel that fails one of these should not exist as drawn.

Test If It Fails
Reachable from the product's own menu?
 Open the real screen; do not rebuild it
Question answerable in one plain sentence?
 No panel. Answer in the conversation and offer the details. The words decide, never the answer size: a "show me" still earns a panel, enriched past the bare number
Did the user ask for what is on screen?
 It should not be there. A panel never opens by itself
Does a designed screen or panel already exist for it?
 Nothing exists to open. Answer in conversation; take the gap to the design backlog
Can the user bring it back through a message or a breadcrumb?
 It breaks Always A Way Back. Give it a message card or a breadcrumb step before it ships
Does anything inside it open a new topic?
 Move that to the conversation or the menu. Inside a panel you can only go deeper (Forward Only)
