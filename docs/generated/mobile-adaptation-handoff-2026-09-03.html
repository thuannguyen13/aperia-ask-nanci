Mobile adaptation checklist

Guidance for adapting Ask Nanci to mobile. Every item is for both design and development. The demo is a preview of the app once every item is applied.

Principles

Three principles decide every item in this checklist. Use them as guidance for anything not covered.

Controls are sized for touch. A thumb covers more screen than a cursor and has no hover. Targets need space around them and not only size.
Nothing disappears without a trace. Content that runs past the edge shows that it continues. Otherwise the user takes a cut-off table for the whole table. Content put away on purpose is fine as long as it can be brought back.
The layout adapts before text or targets do. When space runs out it stacks or scrolls. Sizes stay as they are.

Typography

Text sizes and line heights and how blocks of text are styled.

Requirements
# Priority Requirement Why it matters
1 Required One type scale for both screens. Set the phone size first and step up at the breakpoint rather than defining a new size One scale keeps every size in one place. A heading can be text-xl md:text-2xl. That is text-xl on a phone and text-2xl above the breakpoint
2 Required Every field a user types into is at least 16px. To keep text readable and avoid iOS zoom iOS zooms the whole page when a focused field is under 16px. Set the floor once in the shared input so no screen misses it
3 Optional One class owns the style of a block of text. Today each element carries its own utilities; shadcn/typeset replaces them The container styles everything inside it. A change is one edit rather than one per element

Sizing

How big controls are drawn and how much of them answers a touch.

Requirements
# Priority Requirement Why it matters
1 Required Every tap area is at least 44px. Grow the tap area around the control rather than the control itself Apple asks for 44pt and Google for 48dp. Below that a thumb lands on the control next to the one it meant
2 Required Detect touch instead of screen width. Use Tailwind's pointer-coarse: variant to apply the 44px rule A touchscreen laptop needs the bigger target and a mouse-driven phone does not. Width cannot tell them apart but pointer-coarse: asks the device directly
3 Optional Controls are at least 32px on a phone. Set it in the size variant so the control itself grows on touch and not only its tap area The 44px rule fixes the tap area but not what the user sees. A 24px control is hard to aim at even when its tap area is bigger

Overlays

Anything that opens over the conversation and how it gives the screen back.

Requirements
# Priority Requirement Why it matters
1 Required An open overlay hides what is behind it. Mark everything behind it inert and not only visually covered A screen reader reads through a visual overlay and the user hears two screens at once
2 Required New content announces itself instead of taking the screen. Show a signal the user can act on. Signal once and then stop The user is usually reading when it arrives. Opening over them loses the place they were in, and a signal that repeats becomes a notification
3 Required A phone shows one panel and it slides up from the bottom. Opening another refreshes the content inside the panel that is already there rather than adding a second A phone is too narrow for the column desktop puts beside the conversation. A second panel would cover the first and the user loses what they were reading
4 Required Dialog content fits inside the dialog. Size it in the component and not per dialog Content laid out wider than the dialog is cut off at the edge
5 Optional A dialog stays a dialog on a phone. Adapt its content rather than swapping it for a bottom sheet A sheet is dismissed by dragging, which removes the deliberate choice a confirmation asks for

Screens

The page itself and how a user reaches what is on it.

Requirements
# Priority Requirement Why it matters
1 Required Anything at the screen edge clears the safe area. Pad for the home indicator and the notch rather than sitting flush iOS keeps a strip at the bottom of the screen for the home indicator and a cutout at the top. Anything anchored to an edge sits under them unless it pads with env(safe-area-inset-*), so a composer at the bottom cannot be tapped
2 Required Every screen can be reached on a phone. Give the navbar a phone form rather than leaving it as it is on desktop A desktop navbar does not fit at phone width and any screen linked only from it becomes unreachable. It is the main navigation so its phone form has to be within reach from every screen and not only from the first one
3 Required No screen scrolls sideways as a page. Let the layout stack and keep sideways scrolling inside a table frame A page wider than the screen hides content off the right edge with nothing to show it is there. It usually comes from a fixed width or an element that cannot wrap, so the fix belongs in the layout and not in a scroll container
4 Optional A long list can be searched. Give the user a way to find one row rather than paging to it A phone shows a handful of rows at a time so paging costs far more taps than it does on a desktop. Search turns finding one row into a single action

Charts

Charts at phone width and what they drop to fit.

Requirements
# Priority Requirement Why it matters
1 Required A chart takes its width from its container. Never set a fixed width on it A fixed width pushes the whole screen sideways at phone width
2 Required The chart shows fewer axis labels when space runs out. Let it skip the ones that would overlap Charts skip labels on their own unless told not to. Forcing all of them gives an unreadable row, and if every label matters the chart needs more room
3 Required Nothing is hover only. Whatever a hover reveals answers a tap as well A phone has no hover so a hover-only value cannot be read at all
4 Required A long label is not cut off at the chart edge. Add margin where labels are long or turned The default margin fits a number and not a word so a turned month name runs past the edge and is clipped
5 Optional Every chart behaves the same way on a phone. Set margins and legend placement in the shared chart container and not on each chart Values retyped in each chart drift apart as they are edited. A new chart starts with none of them
6 Optional The legend sits below the chart. Keep it outside the plot rather than floating it inside A legend inside the chart wraps at phone width and the chart is never told it grew so it draws over the plot
7 Optional A dense chart can be opened full screen. Give the user a way to expand it instead of shrinking the data to fit A phone axis holds six or eight readable points and thinning does not make thirty legible. The expanded view has to work in portrait because Safari cannot be told to rotate

Table

Tables wider than the screen and how they scroll.

Requirements
# Priority Requirement Why it matters
1 Required A wide table scrolls sideways inside its own frame. Keep columns at a readable width rather than squeezing them to fit Squeezed columns wrap every cell into a stack of single words. Scrolling inside the frame also keeps the page still
2 Required The right edge shows there is more. Fade the last column rather than cutting it off cleanly A table that stops neatly at the edge looks complete and the user never thinks to scroll

Resources

Published guidance behind the three principles.

Touch Targets on Touchscreens, Nielsen Norman Group. A target of at least 1cm, because a thumb covers about 2.5cm, and spacing that matters as much as size.
The Illusion of Completeness, Nielsen Norman Group. Why a screen that looks finished stops the reader, and what signals that more is there.
Beware Horizontal Scrolling, Nielsen Norman Group. What people miss when content runs off the edge, and why a cue shown only on hover reaches nobody.
Defer Secondary Content When Writing for Mobile Users, Nielsen Norman Group. Layering content by priority rather than cutting it.
Progressive Disclosure, Nielsen Norman Group. Deferring on purpose, which is the difference between layered and hidden.
Reflow, Success Criterion 1.4.10, Web Content Accessibility Guidelines. Content at 320px with no sideways scrolling and nothing lost.
