Mobile foundationRecommendations and practices to follow

What to settle before mobile work starts.

Overview

This report lists what we have today and what we should do before building for mobile.

A phone is not a narrow desktop. The input is a thumb, not a pointer, so targets need more room and anything that depends on hover has nowhere to go. The screen is roughly a third the width, so a layout built in columns has to scroll, stack or drop. And the reader is usually one-handed and moving, not seated in front of it.

Charts

Recharts fits a chart to any width and thins its own ticks. Everything about that width being small is ours to decide.

Recommendation
StateWhat it isWhat to do
In placeFits any width. ResponsiveContainer redraws a chart at its parent’s size—
In placeTicks thin out. Labels drop on their own when they would collide—
In placeTouch works. Tooltips answer a tap, Brush drags—
MissingNo mobile mode. How many labels show, margins, legend and tooltips are all ours to setSet these once in a shared chart wrapper, not chart by chart
MissingLong labels get clipped. The default margin is 5px on every sideAdd more margin where labels are long or turned
MissingLegend height is a guess. The legend never reports it, so the chart cannot make room when entries wrapPut the legend below the chart as a normal element
VerifyThinning can be switched off. interval={0} forces every labelCheck no chart sets it
