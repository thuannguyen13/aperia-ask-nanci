01

How It Works

Think of the AI as a developer who can read your Figma files. You make a change in Figma, share the link, describe what you did, and the AI updates the code so the app matches. You review it in the browser and say what looks right or wrong.

You update
Figma
→
You share the link
+ describe the change
→
AI reads the design
and updates the code
→
You check it
in the browser

That's the whole loop. You stay in Figma — the AI handles the code.

You never write code. Your job is to make good designs in Figma and describe clearly what changed. The more specific you are, the better the result.
02

Environment Setup

You only do this once. It takes about 20–30 minutes the first time, and a developer should sit with you while you do it. After this, your daily routine needs none of it.

Do this with a developer present. Not because it's hard — but because if anything goes sideways, they can fix it in 30 seconds. Once it's done, you won't need their help again for day-to-day work.

First — what is Terminal?

Terminal is a built-in Mac app that lets you type commands directly to your computer. Think of it like texting your Mac — instead of clicking buttons, you type an instruction and your computer does it.

You don't need to understand how it works. You just need to open it and copy-paste the commands in this guide.

How to open Terminal on a Mac:

  • Press Cmd + Space to open Spotlight search
  • Type Terminal
  • Press Enter

A window will open with a blinking cursor. That's Terminal. Everything you type there runs as a command. When a step in this guide shows a dark box like the ones below, that's what you type into Terminal.

Paste with Cmd + V, not Cmd + Shift + V. And always press Enter after pasting a command to run it. Nothing happens until you press Enter.
1

Install Node.js

Node.js is a behind-the-scenes tool that runs the app on your computer. Go to nodejs.org and look for the LTS version. Under it, click the macOS Installer (.pkg) button — it's the green button on the left. Open the downloaded file and follow the installer steps, just like any other Mac app.

When it's done, open Terminal and check it worked by typing:

node --version You should see something like v20.x.x printed back. If you do, Node is installed.
2

Get the project files onto your Mac

Ask a developer for the repository URL. Then type the following into Terminal, replacing the URL with the one they gave you, and press Enter:

git clone https://github.com/your-org/your-project Make sure to include the full URL path after "git clone" — that's what tells git which project to download. Then press Enter.

This downloads the project files into a new folder on your Mac. You only do this once.

Next, move Terminal into that folder. The easiest way is to drag the folder straight into Terminal:

💡 Drag the folder instead of typing.
  1. Type cd (with a space after it) in Terminal — but don't press Enter yet
  2. Open Finder and find your project folder
  3. Drag the project folder from Finder and drop it onto the Terminal window (after cd and the space)
  4. The full folder path fills in automatically — now press Enter

Or if you prefer to type it:

cd your-project Replace "your-project" with the actual folder name. The developer can tell you what it is.

Then install the project's dependencies:

npm install This might take a minute. Wait until the cursor comes back before moving on.
3

Install Claude Code

Claude Code is the AI tool you'll use to send design changes. Install it by pasting this into Terminal and pressing Enter:

npm install -g @anthropic-ai/claude-code The -g means "install globally" — so it works in any folder, not just this project.
4

Connect Claude to your Figma account

Claude needs permission to read your Figma files. Here's how to get that set up:

  • Open Figma and go to Settings → Security → Personal access tokens
  • Click Create new token, give it a name like "Claude", and copy the token it gives you
  • Keep that token somewhere safe — you won't be able to see it again after you close the dialog
  • Hand the token to the developer sitting with you — they'll paste it into Claude's settings for you
Keep your token private. Don't paste it into Slack, email, or a shared doc. It's like a password.
5

Get a GitHub token so you can push your work

When you upload your changes to the shared codebase (called "pushing"), GitHub will ask for a password. It doesn't accept your regular GitHub password — you need a special token instead. Here's how to get one:

  • Go to github.com and sign in
  • Click your profile photo in the top-right corner → Settings
  • Scroll all the way down the left sidebar to the very bottom and click Developer settings (it's the last item)
  • Click Personal access tokens → Tokens (classic)
  • Click Generate new token → Generate new token (classic)
  • Give it a name like My Mac and set an expiration (90 days is fine)
  • Under Select scopes, tick the repo checkbox — that's all you need
  • Scroll down and click Generate token
  • Copy the token immediately — GitHub will only show it once
Save the token somewhere safe right now — in your password manager or a private note. Once you leave that page, GitHub won't show it again. If you lose it, you'll need to generate a new one.

The first time you run git push, Terminal will ask for your GitHub username and password. Enter your username, then paste this token as the password. Your Mac will remember it from then on.

✓

All done

Your Mac now has everything it needs. From here on, your daily routine is: open Terminal, navigate to the project folder, type two commands, send your prompt. That's it — no more installs.

03

Saving and Sharing Your Work

When the AI updates the code, those changes only live on your computer. To share them with the rest of the team — or get them into the real app — you need to save them to the shared codebase. That system is called git.

Think of git like Google Docs version history, but for code. Every save is recorded, nothing gets lost, and everyone on the team can see what changed and who changed it.

The golden rule: always do your work on your own branch. A branch is like your own copy of the project — you can make changes freely without affecting what everyone else sees. When you're happy with the result, you hand it to a developer who merges it in.

The four commands you need

You'll use these in Terminal, inside your project folder. That's it — just four.

1

Create your own branch — do this before you start any work

Give the branch a short name that describes what you're working on. Use dashes, no spaces.

git checkout -b your-branch-name Example: git checkout -b kb-banner-redesign

You only do this once per piece of work. From here, all changes stay on your branch.

2

Save your changes — do this when the result looks good

First, stage everything that changed:

git add .

Then write a short note describing what you did:

git commit -m "your note here" Example: git commit -m "move KB banner to welcome screen"

Keep the note short and specific. A few things to watch out for:

  • The message must be wrapped in quotes — don't leave them out
  • Keep it to one line — no line breaks inside the quotes
  • Avoid special characters like &, ', or " inside the message
3

Push to the shared repo — do this when you're ready for others to see it

git push origin your-branch-name Example: git push origin kb-banner-redesign

This uploads your branch so the team can see it. Nothing goes live yet — it's still just your branch.

If you get an error when pushing, try these:
  • Wrong branch name — run git branch to see your current branch name, then use that exact name in the push command
  • Asked for a username and password — enter your GitHub username, then paste your GitHub token (from Step 5) as the password
  • "Updates were rejected" — run git pull origin your-branch-name first, then try pushing again
  • Still stuck? Ping a developer — push errors are usually quick to fix with a second pair of eyes
4

Tell a developer it's ready

Ping a developer and let them know your branch is pushed and ready to review. They'll open a pull request — a formal request to merge your changes into the main codebase — and take it from there.

Starting fresh work the next day

Before you start a new piece of work, always switch back to the main branch first so you're starting from the latest version:

git checkout main
git pull This switches to main and downloads any updates the team has made since you last worked.

Then create a new branch for the new work (step 1 above).

Never work directly on main. Always create a branch first. If you're unsure what branch you're on, run git branch — the one with a star next to it is your current branch.

Quick reference card

🌿
Start new work — git checkout -b my-branch-name
💾
Save progress — git add . then git commit -m "what I did"
☁️
Share with team — git push origin my-branch-name
🔄
Get latest before starting — git checkout main then git pull
04

Your Everyday Workflow

Every time you want a Figma change to show up in the app, follow these steps.

1

Make your change in Figma

Design as normal. When you're happy with the change and want it in the app, move to step 2.

2

Copy the link to the frame you changed

In Figma, click the frame (the screen or section you updated). Right-click it and choose Copy link to selection. See Section 04 for how to make sure you've got the right kind of link.

3

Open Terminal and start the app

Press Cmd + Space, type Terminal, press Enter. Then navigate to the project folder — type cd (with a space), drag your project folder from Finder into the Terminal window, and press Enter. Then start the app:

npm run dev Keep this Terminal window open — don't close it. The app stops if you do.

Open localhost:3000 in Safari or Chrome. You should see the running app.

4

Open a second Terminal tab and start Claude

Press Cmd + T to open a new tab in the same Terminal window. Navigate to the project folder again the same way — type cd , drag the folder in, press Enter — then start Claude:

claude

Claude Code opens in that tab. This is where you'll type your prompts. Keep both tabs open.

5

Describe your change and paste the Figma link

Type a message to Claude explaining what you changed and paste the Figma link. See Section 05 for examples of what to say.

6

Check the result in the browser

Switch back to your browser at localhost:3000. The page refreshes automatically when Claude finishes. Compare it to your Figma design. If something looks off, tell Claude what's wrong — see Section 07.

7

Save and push when you're happy

Once the result matches the design, save your work and push it so the team can see it:

git add . git commit -m "brief description of what you changed" git push origin your-branch-name

Then ping a developer to let them know it's ready. See Section 03 for a full refresher on the git steps.

05

Getting the Right Figma Link

This is the step that trips people up the most. The AI needs a link to the specific frame you changed — not the whole file.

The right way

In Figma, click the frame you want (the screen or section that contains your change). Then right-click → Copy link to selection.

A good link looks like this — notice the node-id part at the end:

https://www.figma.com/design/pRnyi3pZOjICYkhl8xm348/Ask-Nanci?node-id=7098-220562

How to know if something is wrong

✅
Good — the link ends with ?node-id= followed by numbers. This points to the exact frame.
❌
Bad — the link ends with just the file name and nothing after it. This points to the whole Figma file, not a frame. Claude won't know which screen to look at.
❌
Bad — you copied the link from your browser's address bar while viewing Figma. That gives the page link, not the frame link.
Always right-click the frame and use Copy link to selection. Don't copy from the browser address bar or the Share button.
06

What to Say to the AI

You don't need to be technical. Just describe the change the way you'd explain it to a colleague. Tell Claude three things:

  • What changed — describe the difference between before and after
  • Where it is — which part of the screen (sidebar, header, card, button, etc.)
  • The Figma link — so Claude can see the updated design itself

Moving something

I moved the Knowledge Base card from the bottom of the sidebar to just below the New Chat button. Please look at this Figma frame and update the code to match.

https://www.figma.com/design/pRnyi3pZOjICYkhl8xm348/Ask-Nanci?node-id=7098-220562

Changing how something looks

I updated the Knowledge Base card in the sidebar. It now has a green background tint and a thick green border on the left side instead of the plain white card. There's also a small amber badge that says "Not set up" next to the title.

Please look at this Figma frame and apply those visual changes to the card.

https://www.figma.com/design/pRnyi3pZOjICYkhl8xm348/Ask-Nanci?node-id=7098-220562

Changing text or labels

I updated two labels in the sidebar — the button that said "Teach Nanci" now says "Add Knowledge" and the card title changed from "Knowledge Base" to "Your Knowledge". Please update the text in the code.

Adding something new

I added a new banner to the main welcome screen — it sits between the chat input and the prompt suggestions. It's a horizontal bar with a green tint, a book icon on the left, a short description, and a "Teach Nanci" button on the right.

Please look at this Figma frame and add the banner in the right position.

https://www.figma.com/design/pRnyi3pZOjICYkhl8xm348/Ask-Nanci?node-id=7098-220562

Swapping an icon

The icon on the Knowledge Base card changed from a document illustration to a book icon. Please update it in the code.
Avoid vague messages. "Can you update the design?" or "Make it look like Figma" won't give Claude enough to go on. Say specifically what changed and where.
07

Checking the Result

After Claude finishes, your browser at localhost:3000 will refresh automatically. Put it side by side with your Figma frame and look for any differences.

What to look for

📍
Position — is the element where you put it in Figma, or is it in the wrong place?
🎨
Color — does the background, text, or border color look right?
📐
Size and spacing — are things too close together, too far apart, too big, or too small?
🔤
Text — are all the labels and copy exactly right?
🔍
Missing pieces — is there anything from the Figma design that didn't show up?

If something looks wrong, just describe it

Stay in Claude Code and send a follow-up message. You don't need to paste the Figma link again unless Claude needs to re-read the design.

Two things look off:
1. The card background is still white — it should be that light green tint from the design.
2. The "Not set up" badge isn't showing up next to the title.
The banner is there but it's below the prompt suggestions — it should be above them, right after the chat input box.
Keep going until it matches. Every follow-up message gets Claude closer to the design. You don't need to get it perfect in one shot — just keep describing what's off and it'll get there.

Checking dark mode

If the app has a dark mode toggle (Ask Nanci has one in the bottom-right corner), click it to switch. Check that your change looks right in both light and dark modes, and let Claude know if anything needs adjusting.
