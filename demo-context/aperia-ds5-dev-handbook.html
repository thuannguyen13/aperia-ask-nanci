00

Who Does What

The pipeline has two roles. Understand which one you're in before you start — they interact at specific handoff points.

Designer
  • Owns the Figma file and the ShadcnDesign Kit
  • Publishes Code Connect snippets to Dev Mode
  • Decides brand tokens (colors, radius, typography)
  • Hands off frames to developers via Figma link
Developer
  • Sets up consuming projects using aperia-ds5
  • Applies theming from the design token spec
  • Uses Claude + Figma MCP to generate UI from frames
  • Wires up state, data, and business logic
  • Reviews, fixes, and ships to staging → production
If you're a developer: you don't need to touch the aperia-ds5 library repo unless you're adding components. Your day-to-day is entirely in your consuming project — install the package, import components, build pages.

Configure the Figma MCP server

Add this to your Claude Code MCP settings (~/.claude/settings.json or via /mcp in Claude Code):

{
  "mcpServers": {
    "figma": {
      "command": "npx",
      "args": ["-y", "figma-developer-mcp", "--stdio"],
      "env": {
        "FIGMA_ACCESS_TOKEN": "<your-figma-personal-token>"
      }
    }
  }
}
Keep your personal token private. Never commit it to git. If you paste it into a .env file, make sure that file is in .gitignore.
02

Where Designs Live

All designs start in Figma. There are two files you'll interact with.

F

ShadcnDesign Kit — the component library source

This is the Figma file that mirrors aperia-ds5. It contains every component, all their variants, and the token/style definitions. The designer maintains this file and publishes it to the team library so it can be used in project files.

You don't edit this file. You use it as a reference when you need to understand what props a Figma component maps to. Code Connect snippets live here — you'll see the real aperia-ds5 import snippets when you select a component in Dev Mode.

P

Project Figma file — the screens you're building

This is the file your designer creates for the specific project. It contains page-level frames using components from the ShadcnDesign Kit. This is the file you get links from when building screens.

How to get the link: the designer right-clicks a frame → Copy link. You'll receive something like https://www.figma.com/design/<fileKey>/<name>?node-id=<nodeId>.

Reading a design in Dev Mode

When the designer shares a frame, open it in Figma and switch to Dev Mode (the </> toggle in the top-right). Select any component — if it has Code Connect set up, you'll see the exact aperia-ds5 import and prop values instead of raw CSS. Use this to verify props before or after AI generation.

Code Connect is live for: Alert, Avatar / AvatarBadge / AvatarGroup, Badge, Button, Checkbox, Empty / EmptyMedia, Icon (all Lucide icons), Input, InputGroup, RadioGroup, Select, Switch, Tabs / TabsTrigger, Textarea. These components show real code in Dev Mode.
03

Set Up a New Project

Follow these steps in order. Each step has exactly one command or action.

1

Scaffold a Next.js project

Use the standard create-next-app command. Choose TypeScript, Tailwind CSS, and the App Router when prompted.

npx create-next-app@latest my-project --typescript --tailwind --app --src-dir=false
cd my-project
2

Install aperia-ds5

Install from the npm registry (npmjs.com/package/aperia-ds5):

npm install aperia-ds5
3

Wire up globals.css

Open app/globals.css and replace its contents with:

@import "tailwindcss";
@import "aperia-ds5/base.css";

/* That's it. base.css brings tw-animate-css, tokens, Radix variants, */
/* and @source for the dist — nothing else needed.                    */

/* Brand overrides go here — see Section 04 */
4

Wrap the app in ThemeProvider

Open app/layout.tsx and add the provider so dark mode works:

import { ThemeProvider } from "aperia-ds5/theme-provider"

// Inside your root layout <body>:
<ThemeProvider defaultTheme="light" attribute="class">
  {children}
</ThemeProvider>
5

Smoke test — render a button

In app/page.tsx, import and render one component to confirm the wiring works:

import { Button } from "aperia-ds5"

export default function Page() {
  return <Button>Hello DS5</Button>
}
npm run dev  # open localhost:3000 — button should render styled
It's working if: the button renders with the default Aperia styling (navy background, white text, rounded corners). If it's unstyled, the most common cause is a missing @source directive in globals.css.
04

Theming the Project

aperia-ds5 ships default tokens in base.css. To apply a brand identity, add a :root override block in globals.css — no other config needed. The designer provides the token values; you copy them in.

The override block

Add this after your imports in globals.css. Override only what the brand changes — leave everything else to the defaults from base.css.

/* globals.css — brand overrides */
:root {
  /* Primary brand color (oklch recommended, hex also works) */
  --primary: oklch(0.42 0.18 252);        /* navy */
  --primary-foreground: oklch(0.98 0 0);  /* white */

  /* Accent / brand highlight */
  --accent: oklch(0.60 0.22 28);          /* brand orange */
  --accent-foreground: oklch(0.98 0 0);

  /* Surface + background */
  --background: oklch(1 0 0);
  --card: oklch(0.97 0.002 286);

  /* Radius (consistent rounding) */
  --radius: 0.5rem;

  /* Typography */
  --font-sans: 'Inter', system-ui, sans-serif;
}

/* Dark mode — same variables, different values */
.dark {
  --background: oklch(0.14 0.005 286);
  --card: oklch(0.20 0.005 286);
}

What tokens are available

The full set is in aperia-ds5.vercel.app → Storybook → Docs. The most commonly overridden tokens:

TokenControls
--primary / --primary-foregroundPrimary buttons, active states, focus rings
--secondary / --secondary-foregroundSecondary buttons, muted surfaces
--accent / --accent-foregroundHover states, accent highlights
--background / --foregroundPage background and body text
--card / --card-foregroundCard surfaces
--destructive / --destructive-foregroundError states, destructive actions
--border / --input / --ringBorders, input outlines, focus rings
--radiusBorder radius across all components
--font-sans / --font-monoBody font, monospace font
Tweakcn shortcut: Go to tweakcn.com, design your theme visually, then copy the generated :root block directly into globals.css. The variable naming is 100% compatible with aperia-ds5.
05

Generate a Screen with AI

This is the core workflow. With the Figma MCP server running, Claude can read the design directly and generate production-ready component code. Follow this exact sequence — skipping steps, especially the spec review, leads to rewrites.

1

Get the Figma link from your designer

Ask for a direct frame link (not a page link). It should look like:
https://www.figma.com/design/<fileKey>/Name?node-id=<nodeId>

If you're handed a page link, open Figma, click the specific frame, then use Copy link from the right-click menu.

2

Open Claude Code in your project directory

cd my-project
claude

Confirm the Figma MCP server is active — you'll see it listed under active tools when Claude starts.

If you've installed the team skills from github.com/Joeperia/ai-team, load the relevant skill now with its slash command before sending Message 1. The skill pre-loads DS5-specific rules so Claude doesn't have to rediscover them mid-generation.

3

Message 1 — fetch and spec (do not code yet)

Send this as your first message:

Fetch this Figma frame and give me the implementation spec for approval.
Go through each section top-to-bottom. For each section note:
- Layout (flex, grid, rows, columns)
- Every component name and its props
- Every icon name
- Every piece of static copy

Do not write any code yet. Wait for my approval.

[paste your Figma URL here]

Claude will call get_design_context, read the screenshot section-by-section, and return a structured spec.

4

Review the spec

Read Claude's spec against the Figma frame. Correct anything wrong — wrong component names, missing sections, invented copy. This is the cheapest moment to fix mistakes. Once you approve, corrections happen in code, which is more expensive.

Reply Looks good, implement it. to proceed, or list your corrections first.

5

Message 2 — implement

Implement the spec as approved.
Use aperia-ds5 components throughout.
Target file: app/[your-page-path]/page.tsx
Do not use inline styles — use Tailwind utility classes only.

Claude will generate the component tree, import all DS components, and write the file.

6

Review the output

Open your browser at localhost:3000. Compare the rendered screen with the Figma frame side by side. Common things to check:

  • Spacing and padding match the design
  • Correct component variant is used (e.g. button variant="outline" not default)
  • Icons are the right names from Lucide
  • No hardcoded hex colors — everything should use tokens
7

Wire up logic

The generated output is UI scaffolding. You own connecting it to real data, state management, event handlers, API calls, and routing. Use targeted Claude messages for specific wiring tasks rather than rewriting the whole file.

Key rule: always run two messages — spec first, code second. Developers who skip the spec review consistently end up with a correction pass that takes longer than the extra message would have.

Cleaning up context between screens

After finishing one screen and starting the next, run /compact in Claude Code. This collapses the previous screen's tool output from the conversation window, keeping generation for the next screen faster and more accurate.

08

Dos & Don'ts

Rules distilled from actual builds. Each don't maps to a real mistake that caused a rewrite.

DoDon't
Fetch the Figma frame before writing any code Start coding from a text description of the design
Read the spec section by section and approve it before asking Claude to implement Ask Claude to "build this page" in a single message
Extract exact copy, counts, and icon names from the Figma output Let Claude invent labels, nav item names, or badge numbers
Use aperia-ds5 components for every UI element in the spec Mix DS components with raw HTML elements for the same type of UI
Use Tailwind utility classes for spacing, sizing, and layout Write inline style={{}} objects — they ignore your token system
Use CSS token variables (--primary, --background) for colors Hardcode hex values — they break dark mode and make theming impossible
Run /compact after completing a screen, before starting the next Let context accumulate across many screens — it degrades generation quality
Give precise fix instructions: file, line, what's wrong, what to do Say "fix the layout" without specifying what and where
Check aperia-ds5.vercel.app for the correct prop names before writing or reviewing code Guess prop names from memory — they change between versions
Verify Code Connect snippets in Figma Dev Mode for mapped components Assume Claude will always choose the right variant without checking

When something looks wrong after generation

1

Is it a component variant issue?

Open the component in Figma Dev Mode (select it → switch to </> tab). If it has Code Connect, the correct variant and props are shown. Compare to what was generated.

2

Is it a layout issue?

Open aperia-ds5.vercel.app Storybook, find the component, and look at the story that matches the design. Copy the correct JSX pattern and use it as a reference for a targeted fix message.

3

Is it a styling / token issue?

Check that globals.css has the @source "../node_modules/aperia-ds5/dist" line. Without it, Tailwind won't include the DS classes. Also confirm @import "aperia-ds5/base.css" is present.

Getting stuck? The quickest path is usually to show Claude the specific element that's wrong along with a screenshot or the Figma frame section — attach the image to your Claude Code message and say "this element should look like the Figma, fix it."
09

compose-layout Skill (AI Team Repo)

The AI Team repo provides a compose-layout Claude skill that automates the entire Figma-to-code pipeline. Instead of running the two-message workflow manually inside your project, you open Claude Code inside the AI repo and let the skill do the heavy lifting — it breaks the design into individual components, generates each one, then assembles a full page component that matches the frame.

When to use this vs. the manual workflow: Use compose-layout for full page or multi-section layouts where you want components generated separately and then composed. Use the manual two-message workflow (Section 05) for targeted additions or when you're iterating on an existing screen.
1

Clone the AI Team repo adjacent to your project

The skill needs to reference your target repo by name, so clone it as a sibling directory — not inside your project.

# Expected directory layout:
~/projects/
  ai-team/          ← clone here
  my-project/       ← your consuming project
git clone https://github.com/Joeperia/ai-team
cd ai-team && pnpm install
2

Add the globals.css file to your target repo

Design provides a globals.css file for the project. Place it in your target repo and import it inside your entry CSS file:

/* app/globals.css */
@import "tailwindcss";
@import "aperia-ds5/base.css";
@import "./[project-globals].css"; /* file provided by Design */
3

Open Claude Code inside the AI repo

Launch Claude from the AI repo directory, not your project. The skill files live there and Claude needs to be in that working directory to load them.

cd ai-team
claude
4

Run the compose-layout skill

Pass two arguments: the Figma frame link and the name of your target repo directory.

/compose-layout figma_link="<figma-url>" target_repo_name="<repo-folder-name>"

Example using the Ask Nanci welcome screen:

/compose-layout figma_link="https://www.figma.com/design/pRnyi3pZOjICYkhl8xm348/Ask-Nanci?node-id=7098-220562" target_repo_name="aperia-ask-nanci"
5

Respond to prompts as they come up

The skill is interactive. You'll be asked to approve commands and verify results at key checkpoints — typically before it writes files into your target repo or runs a build. Read each prompt before accepting.

6

Review the output

The skill breaks the design into separate components, generates each individually using aperia-ds5, then assembles a full page component that matches the Figma frame. Check the result against the design — spacing, variants, icons, and copy — the same way you would after the manual workflow.

+

Optional — generate Storybook stories

At the end of the run you'll be prompted to generate Storybook stories for all the components that were created. Accept this to get component documentation alongside the implementation.

Claude Code must be open inside ai-team/, not your project directory. The skill files won't be found if you launch Claude from the wrong location.
